# anki-claude-mod

A Claude Code mod (plugin name `anki`, listed in the `hbkse` marketplace at
`hbkse/claude-plugins`) that shows due Anki cards above the prompt while Claude works. The repo
name is `anki-claude-mod`; user-facing text says "anki" or "the anki plugin", never the repo name.

## Layout

```
Claude Code ── mod (hooks/register.tsx) ── $.process.run ──▶ sidecar (Rust, Anki's rslib) ──▶ AnkiWeb
```

- `hooks/register.tsx`: the mod. Draws the band above the prompt (only while a turn runs), the
  deck menu, the `/anki` command. Calls the sidecar one command at a time through a promise chain,
  because the sidecar holds an exclusive lock on the collection while it runs.
- `sidecar/src/main.rs`: one-shot CLI over `rslib` (a git dependency pinned to an Anki release tag,
  along with `anki_proto`). Every command opens the collection, does one thing, closes it and
  prints one JSON line: `{"ok":true,...}` or `{"ok":false,"code","message"}`. The mod keys off
  `code`; `message` is shown to people. Commands: `login [--interactive|--from-desktop P]`,
  `desktop-logins`, `local-collections`, `setup --collection P|--reset`, `logout`, `status`,
  `sync [--full-download|--full-upload]`, `decks`, `next [--deck N] [--skip ID]`,
  `answer --card ID --rating R [--ms N] [--at UNIX_MS]`. A card takes about 10 ms.
- `types/index.d.ts`: the mod's state atoms (`PluginState.anki`) and card types.
- `tests/register.test.tsx`: mod tests, with the sidecar faked through `on('process.run', ...)`.
- `scripts/install-sidecar.{sh,ps1}`: run by the mod before its first sidecar call. Installs the
  release pinned in `sidecar.lock` into `bin/` if its SHA-256 matches; a local build marked by
  `bin/.dev` always wins.
- `.claude-plugin/types/`: generated by Claude Code when it loads the plugin (gitignored);
  `tsconfig.json` extends it.

## Data

`dirs::data_dir()/anki-claude-mod/` (`$ANKI_CLAUDE_MOD_DIR` overrides it):
- `collection.anki2`: the sidecar's own copy, synced with AnkiWeb.
- `auth.json` (0600): email, sync key (`hkey`), endpoint (AnkiWeb redirects to a shard; the new
  endpoint is saved), `has_synced`. Never the password.
- `local.json`: the collection `/anki setup` points at. Used only while there's no `auth.json`:
  AnkiWeb takes priority.

The mod keeps the picked deck in `$.store` (`deck`).

## Design decisions

- **Login** never goes through Claude Code: `/anki login` either reuses Anki desktop's sync key
  (read from `Anki2/prefs21.db`, a pickled dict per profile) or opens a terminal window running
  `sidecar login --interactive` (hidden password via rpassword). The window is opened in the
  host terminal, detected from env vars (`launchers()` in register.tsx), falling back to the OS
  terminal, then the clipboard. The window links to the README's
  `#ankiweb-password-information` section; if that heading changes, change the link too.
- **Undo**: rslib's undo lives only while a collection is open, and the sidecar is one-shot, so
  the mod holds the last grade back (`pending`) and commits it on the next grade, a sync, a deck
  switch or session end. `next --skip` deals around the held card; `--at` records press time.
- **Local decks**: SQLite blocks everyone, reads included, while Anki desktop holds its
  collection, so `check_local` probes on a thread and reports `desktop_open` after 500 ms; the mod
  then shows "paused" and retries next turn without awaiting. Collections with schema != 18
  (Anki < 2.1.50) are refused rather than upgraded.
- **Card text**: `rich()` turns rendered HTML into lines of styled runs (bold/italic/underline/
  colour, furigana as readings), dropping comments, scripts and styles first (note types keep
  template blocks in comments). The mod draws ruby lines as wrapping rows of two-row columns.
  `plain_lines()` is the bracket fallback (`置[お]く`).
- **Messages**: command replies are toasts, not `{ text }` (command text lands in the transcript
  the model reads). Every AnkiWeb message and sync error is surfaced.

## Mod API gotchas

- Hooks run with no fs, network or Node: everything goes through `$` (`$.process.run`,
  `$.http.fetch`, `$.store`, `$.env.get` with literal names only).
- A function that takes `$` can't share its name with anything else in the file (a local
  variable, a parameter): the module refuses to load. This bit us with `host` and `run`.
- `$.process.run` is one-shot and waits for exit: start GUI programs detached.
- `$.config.set` can't change `sensitive` fields, and returns `{ deny }` rather than throwing.
- Plugin names can't start with `claude-`.
- Test kit: `ui.find` matches text by inclusion (use `findAll` and anchored regexes for nested
  Text), and presses buttons by `key`, not hotkey.

## Develop

Building the sidecar needs Rust and `protoc` (`brew install protobuf`); the first build compiles
Anki's core and takes a few minutes.

```sh
./scripts/build-sidecar.sh       # release build into bin/, marked as a local build (.dev)
claude --plugin-dir .
claude plugin validate .
claude plugin test .
npx -p typescript@5 tsc -p .     # typecheck against .claude-plugin/types
cargo test --manifest-path sidecar/Cargo.toml
```

Debug-build-only sidecar commands: `seed N [DECK]` (adds Basic notes), `hold --secs N` (holds the
collection open like Anki desktop, to test locking), `inspect --n N` (due cards' raw HTML beside
what's drawn). `ANKI_CLAUDE_MOD_DESKTOP_DIR` points desktop detection at a fake `Anki2` folder.

Anki's `anki-sync-server` works as a local AnkiWeb for sync tests:
`cargo install --git https://github.com/ankitects/anki.git --tag <tag> anki-sync-server`, run it
with `SYNC_USER1=user:pw`, and log in with `"endpoint": "http://127.0.0.1:27701/"` in the JSON on
`sidecar login`'s stdin. `ANKI_CLAUDE_MOD_RELEASE_URL` points the installer at another download
location; the checksum is still checked.

## Release

Push a tag like `v0.3.0`. `.github/workflows/release.yml` builds the sidecar for darwin-arm64,
darwin-x64, linux-x64/arm64 (static musl) and windows-x64, publishes a GitHub release, then
commits `sidecar.lock` (the SHA-256s) and the plugin version to the default branch. Installed
plugins are cached by version, so that bump is what makes `/plugin update` pick a release up.
Pull after a release before committing again.

When bumping the Anki tag in `sidecar/Cargo.toml`, check the schema version (`SCHEMA_VERSION`) and
the rslib APIs the sidecar uses (`get_queued_cards`, `answer_card`, `render_existing_card`,
`normal_sync`, `deck_tree`).
